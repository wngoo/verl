This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is verl

verl is a flexible, efficient RL training library for LLMs (ByteDance Seed's open-source HybridFlow). It supports PPO, GRPO, REINFORCE++, RLOO, DAPO, and 20+ other RL algorithms at scale (up to 671B+ models).

## Development Setup

```bash
pip install -e .[test,vllm]    # or .[test,sglang]
pip install pre-commit hydra-core
pre-commit install
```

## Commands

**Linting/Formatting:**
```bash
pre-commit run                          # staged changes only
pre-commit run --all-files              # all files
pre-commit run --all-files --show-diff-on-failure --color=always ruff
pre-commit run --all-files --show-diff-on-failure --color=always autogen-trainer-cfg
```

**Testing:**
```bash
pytest -s -x --asyncio-mode=auto tests/         # CPU unit tests (test_*_on_cpu.py)
pytest tests/ -x                                # GPU unit tests
```

Test categories: `tests/trainer/`, `tests/models/`, `tests/workers/`, `tests/special_distributed/` (multi-GPU), `tests/special_e2e/`, `tests/special_sanity/`.

**Docs:**
```bash
cd docs && pip install -r requirements-docs.txt
make clean && make html
python -m http.server -d _build/html/
```

**Training entry point:**
```bash
python -m verl.trainer.main_ppo \
  --config-path trainer/config \
  --config-name ppo_trainer \
  actor_rollout_ref.actor.strategy=fsdp
```

## Architecture

### Distributed Execution Model

verl uses a **hybrid controller** pattern via Ray:
- A `TaskRunner` Ray remote actor orchestrates the training loop
- Workers are placed on GPU resource pools via Ray; the trainer coordinates them
- All data between workers flows as `DataProto` (a TensorDict wrapper defined in `verl/protocol.py`)

### Core Components

**`verl/trainer/`** — Training orchestration
- `main_ppo.py`: Entry point; uses Hydra for config loading
- `ppo/ray_trainer.py`: Distributed PPO loop (rollout → reward → train)
- `config/`: Modular YAML configs; `_generated_*.yaml` files are auto-generated by pre-commit — do not edit manually

**`verl/workers/`** — GPU workers
- `fsdp_workers.py` / `megatron_workers.py`: Training workers by backend
- `engine_workers.py`: New unified engine workers
- `rollout/vllm/` and `rollout/sglang/`: Inference engine integrations
- `reward_manager/`: Model-based and function-based reward scoring

**`verl/single_controller/`** — Distributed coordination
- `base/worker.py`, `base/worker_group.py`: Worker abstractions
- `base/decorator.py`: `@register` decorators for dispatching computation to worker groups
- `ray/`: Ray-based implementations of the above

**`verl/models/`** — Model implementations
- `transformers/`: HuggingFace models
- `mcore/`: Megatron-LM models
- `registry.py`: Model registry

**`verl/utils/`** — Utilities
- `device.py`: Hardware abstraction (CUDA/NPU) — use this instead of hardcoding `.cuda()`
- `fsdp_utils.py`: FSDP sharding helpers
- `dataset/`: Data loading and sampling

**`verl/experimental/`** — Experimental features (async training, off-policy, agent loops, VLA)

### Data Flow

```
DataProto (TensorDict) moves between workers:
  ActorRolloutRefWorker (generate) → RewardManager (score) → TrainingWorker (update)
```

`DataProto` handles padding, batching, and distributed tensor slicing. It is the **only** sanctioned way to pass tensors between components.

### Configuration System

Configs live in `verl/trainer/config/` and use Hydra's structured config composition. Key top-level groups: `actor_rollout_ref`, `critic`, `reward_model`, `algorithm`, `trainer`. Worker behavior is configured via dataclasses in `verl/workers/config.py`.

## Key Conventions

- **Device API**: Always use `verl.utils.device` utilities rather than calling `.cuda()` directly — supports both NVIDIA and Ascend NPU.
- **Generated configs**: Files matching `_generated_*.yaml` are produced by the `autogen-trainer-cfg` pre-commit hook. Never edit them by hand.
- **Naming**: Use "verl" (lowercase) in code and prose; "veRL" is only for the logo/branding. Use "SGLang" (not "sglang" or "Sglang") in user-facing text.
- **Line length**: 120 characters (enforced by ruff).
- **License headers**: All Python files need the Apache 2.0 header (enforced by `check-license` pre-commit hook).
- **CPU-only tests**: Name files `test_*_on_cpu.py` so CI routes them to CPU runners.
